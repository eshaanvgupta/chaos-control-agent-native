# Security and operational boundaries

- Framework authentication remains enabled. Guest access uses a cryptographically random 256-bit HttpOnly, SameSite=Lax cookie. Only its SHA-256 hash is stored server-side; it expires after seven days. The session is attached using Agent-Native's supported additional-session adapter, not a shared demo identity. HTTPS enables Secure cookies.
- Every domain read/write filters by owner and verifies workspace parent access. UUIDs are identifiers, never access grants. Guests cannot read another guest's workspace. Persistent sign-in and organization settings use the framework's existing authenticated surfaces; team collaboration is not claimed for private operational workspaces.
- Inputs use bounded Zod schemas. Six-table CSV imports cap each table at 1 MB and validate all fields and references before writes. React escapes uploaded text. Spreadsheet-safe exports prefix formula-like strings. Imported content is never evaluated as code or treated as agent instructions.
- Drizzle binds ordinary queries. The fixed migration SQL is application-owned. Runtime databases, cookies, keys, logs and environment files are ignored by Git. Provider credentials stay in the framework's supported vault/connection paths.
- Normal mutations require a current revision. Application is an atomic transaction. Concurrent updates cannot both overwrite the same revision. Repeated application of an already applied plan returns its prior success without a second mutation.
- Approval is human-only (`frontend`, authenticated `http`, or deliberate local `cli`); the tool/agent caller is rejected. Approval is tied to the exact stored plan and base revision. `approve-plan` is hidden from agent/MCP/extension tool catalogs. The native agent's action surface is allowlisted, raw database tools and production code execution are disabled, and the app does not enable the source-editing harness. A trusted developer with server/database access is outside this product approval boundary.
- Snapshot audit events record actor surface, revisions, details, before/after state and UTC timestamps. Undo appends new history rather than deleting evidence. There is no external purchasing or shipment API.

Production operators must provide HTTPS, persistent PostgreSQL backups, request/rate limits at their ingress, a stable Better Auth secret, and deployment-specific email/OAuth policy if using those account features. This repository has no certification or independent penetration-test claim. Guest sessions are suitable for isolated demos; use authenticated accounts for business data that must outlive a browser cookie. Export before clearing cookies.
