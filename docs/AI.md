# Actual AI runtime

The full local app's model interactions run through the original Agent-Native chat bridge, AgentKit controller, model settings and native agent tool loop. The public GitHub Pages edition separately offers an optional read-only browser analyst with the user's own OpenRouter or Groq key. It sends requests directly to that provider and keeps the key only in tab memory. See [BYOK behavior and privacy](BYOK.md). This does not demonstrate a native agent tool-calling conversation. Every numerical operation remains available without AI.

**Builder.io:** open Workspace settings → Model (the framework route `/settings/model`), choose Builder.io and follow its supported connection flow. A connected development account is not automatically a free public inference grant. Credits, eligibility and limits depend on the actual account. If the connection fails or credits expire, use the deterministic workflow and follow the native setup/error state.

**Optional local Ollama:** run `pnpm ollama:setup` then `pnpm dev:ollama`. On Windows the helper downloads the official portable runtime when needed, starts a loopback service and pulls qwen3:1.7b model weights into ignored `.runtime` storage. On other operating systems install Ollama first. Existing installations are reused. Check with `pnpm ollama:doctor`; choose another tool-capable model with `-- --model your-model:tag`. Open `/settings/app/ollama` for native connection checks and provider settings. That native provider dialog saves connection settings; its storage behavior differs from the public browser popup. Use `--endpoint http://127.0.0.1:11434` to change the CLI endpoint. Do not expose unauthenticated Ollama publicly. No model download or generation is claimed successful without verification.

**Observed verification boundary:** the provider-independent tools are tested. A live Builder/Ollama tool-calling conversation has not been asserted successful without a configured provider. Native chat displays the actual setup requirement or error. The UI explicitly labels deterministic specialist tools.

Suggested real model demonstration after connection: select `WH-WEST` in Operations World and ask, “Why is this warehouse at risk? Read view-screen and inspect operational state. Find the cheapest feasible response and compare it with the fastest. Do not execute until I approve.” Inspect the visible real tool events, approve in Strategy Lab, then ask the agent to apply that approved plan and verify the new state.
